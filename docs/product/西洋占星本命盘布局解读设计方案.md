# 西洋占星本命盘布局解读设计方案

> 前置方案：[西洋占星生活化解析设计方案](西洋占星生活化解析设计方案.md)（行运 / 日运链路 A0-A8）
> 本方案是与之并列的**本命盘静态解读**链路，编号 N1-N5。
> 本轮聚焦：已经排出来的「黄道与宫位布局」如何被读出来、讲清楚。

## 1. 背景与目标

西洋占星页现在的「本命盘」页签已经把黄道、宫位、四轴、星体和相位画成了可读的圆盘（`c4b853f`），「结构事实」页签提供原始表格，「解析提示词」页签给出交给外部 AI 的结构化 JSON。也就是说**事实已经完备，缺的是页面内的解读层**。

本方案增加一条「本命盘结构化事实 → 布局信号 → 可读解读卡片」的链路：

- 用户不复制提示词、不离开页面，就能看懂自己盘上的黄道与宫位布局；
- 每条解读都能回溯到星体、星座、宫位、黄经、相位容许度和配置版本；
- 解读是对结构化事实的表达，不改变排盘结果，也不引入新的事实；
- 普通模式易读，专业模式可核对，研究模式保留规则与未覆盖项。

参考「测测」一类产品星盘解读的**信息架构和阅读节奏**：先给上升 / 太阳 / 月亮三个核心，再读宫位分布（半球、象限、空宫），然后按星体逐条展开落座落宫，最后补相位与元素模式。本方案不复制竞品文案、插画或图标资产。

## 2. 竞品参考拆解

### 2.1 实测来源

以测测官方 H5 教程为参考对象（不是凭印象概括）：

- [三分钟入门星盘](https://www.xxwolo.com/p_engine/apph5/pan_course.php)：三核心、宫位半球读法、相位颜色语义、`A星B座C宫` 组合公式；
- [行星、星座、宫位的象征](https://www.xxwolo.com/p_engine/apph5/astro_course3.php)：十大行星 + 南北交点、十二星座、十二宫位的象征词表。

### 2.2 阅读顺序

测测一类 App 的星盘解读大致遵循以下顺序，本项目借鉴的是这个顺序本身：

1. 首屏三大核心（上升、太阳、月亮），一句话定性；
2. 宫位布局速读：星体集中在左半还是右半、上半还是下半，哪几宫是空的；
3. 按星体逐条展开「落在哪个座、落在第几宫」，每条配一段解读；
4. 十二宫位说明（宫头星座、宫内星体、宫主星去向）；
5. 相位解读（哪些点连在一起、意味着什么，偏顺畅还是偏张力）；
6. 元素 / 模式分布概览（火土风水、基本固定变动）；
7. 专业信息折叠在二级层，普通用户默认不看到术语。

### 2.3 测测对「布局」的具体读法

教程原文给出的三条布局读法，是本方案布局层的直接依据：

| 布局维度 | 测测的读法 | 本项目落点 |
| --- | --- | --- |
| 左右半球 | 星体多落 1、2、3、10、11、12 宫（左半）→ 更关注自我、主观；多落 4-9 宫（右半）→ 更关注他人、愿意配合 | `hemispheres.left/right` 计数 + 点位，普通模式给一句结构描述 |
| 上下半球 | 多落 7-12 宫（上半）→ 活跃于公共事务、需要外界肯定；多落 1-6 宫（下半）→ 低调、注重隐私 | `hemispheres.above/below` 计数 + 点位 |
| 相位颜色 | 蓝绿线代表和谐顺畅，红紫线代表矛盾冲突；顺畅多 → 更知道要什么，冲突多 → 常面临取舍 | `aspect_network.harmony/tension` 计数，措辞用「顺畅 / 张力」 |
| 组合公式 | 「A 星 B 座 C 宫」逐条套：太阳狮子 10 宫 = 人格 × 骄傲热情 × 事业 | `point_core × sign_style × house_field` 组合式渲染 |

注意：测测把半球读法当作**性格倾向**直接下结论。本项目只把它作为**结构集中度**的描述，倾向措辞统一收敛到「倾向 / 可能 / 适合留意」。

### 2.4 差异点

本项目把「每条解读可回溯到规则与证据」作为硬要求：

- 不做无来源的断语，每个数字都能追到 `structured` 字段与点位 ID；
- 不做分数化的吉凶排名，相位不判吉凶；
- 半球 / 象限只描述**星体落在盘面的哪一部分**，不断言性格与现实结果。

| 模式 | 面向 | 内容 |
| --- | --- | --- |
| 普通模式 | 只想看懂盘的普通用户 | 三大核心卡、布局速读条、行星卡片一句话、展开后的三段解读、分布条；术语默认折叠 |

## 4. 可用的排盘事实（现状盘点）

`POST /api/v1/astro/charts` 返回的 `data.structured`（`astro-structured/1.0`）已经提供了解读所需的全部事实，**本方案不新增排盘计算，也不改 C++ 排盘核心**：

| 字段 | 关键子字段 | 用途 |
| --- | --- | --- |
| `points[]` | `id`、`longitude`、`degree_in_sign`、`sign_id`、`house`、`motion.retrograde`、`classification.element/modality` | 行星落座 / 落宫 / 逆行卡片、半球与象限统计 |
| `angles[]` | `id`、`longitude`、`sign_id`、`sign_name` | 三轴卡片、四轴说明 |
| `houses[]` | `number`、`cusp`、`sign_id`、`sign_name`、`element`、`modality` | 十二宫卡片、宫头星座、空宫判定 |
| `aspects[]` | `source_id`、`target_id`、`type`、`orb`、`phase` | 相位卡片、相位网络统计 |
| `aggregates` | `element_counts`、`modality_counts`、`house_counts`（键为字符串宫号） | 元素 / 模式 / 落宫分布 |
| `derived_signals.signals[]` | `signal_id`、`type`、`point_ids`、`evidence` | 角宫星体、逆行、强调元素/模式、星体群、紧密相位 |

落地时必须注意的字段差异（两侧视图不同，不能混用）：

- `structured.angles` 是**数组**，按 `id`（`ascendant`/`midheaven`/`descendant`/`imum_coeli`）索引；而 `/charts` 平铺视图的 `angles` 是**对象**。解读层统一按 `structured` 处理。
- `structured.points[]` 有 `sign_id`，但**没有 `sign_name`**；中文座名由模板库的 `sign_style[sign_id].label` 提供，不在 Python 里硬编码第二份。
- `structured.aspects[]` 用 `source_id`/`target_id`，平铺视图用 `first`/`second`；解读层只用 `structured`。
- `points[]` 含 `true_node`（可能还有 `chiron`）。凡是计数类统计都必须显式声明统计口径，并回传被计入的 `point_ids`。

因此事实层信号一律**从 `structured` 在 Python 侧派生**（`web/astro_natal_analysis.py`），不修改 C++ 排盘核心、不触发全量重建；这与行运链路的做法一致。

## 5. 解读内容架构

### 5.1 布局速读（N1 首先交付）

「排出来的黄道与宫位布局」本身可读，靠的是一层**只描述结构、不下结论**的速读层。它全部由 `structured` 统计而来，每项都带口径和点位清单：

| 速读项 | 计算口径 | 一句话示例 |
| --- | --- | --- |
| 三大核心 | `angles.ascendant`、`points.sun`、`points.moon` | 上升处女 · 太阳金牛（第9宫）· 月亮双鱼（第7宫） |
| 左右半球 | 十大行星的 `house ∈ {1,2,3,10,11,12}` vs `{4,5,6,7,8,9}` | 10 个行星里有 8 个落在右半盘，结构重心偏向这一侧 |
| 上下半球 | 十大行星的 `house ∈ {7,8,9,10,11,12}` vs `{1,2,3,4,5,6}` | 上、下半盘各 5 个，分布接近平衡 |
| 四象限 | 十大行星按 `1-3 / 4-6 / 7-9 / 10-12` 计数 | 第二、第三象限各 4 个，是第一、第四象限的 4 倍 |
| 星座占据 | 十大行星按 `sign_id` 计数 | 摩羯座 3 个行星，双子座、狮子座等为空 |
| 空宫 | `houses[]` 中无十大行星落入的宫 | 第 1、3、5、11、12 宫没有行星落入 |
| 元素 / 模式 | `aggregates.element_counts / modality_counts` | 土 5、水 5 高于火 1、风 1；基本 6 最集中 |
| 相位网络 | `aspects[]` 按类型计数与平均容许度 | 主要相位 9 条，其中顺畅 5 条、张力 3 条、紧密相位 2 条 |
| 角宫星体 | 复用 `derived_signals.angular_planet` | 月亮落在角宫，靠近四轴 |
| 逆行 | 复用 `derived_signals.retrograde_point` | 木星、土星逆行的表达偏向内回看 |

速读层的定位是「**把图读成句子**」，所以：

- 每条都返回 `evidence`（计数、阈值、点位 ID、宫号集合）与 `definition`（统计口径说明）；
- 一段话里不出现吉凶、评分、性格定论；
- 数字为 0 或口径不适用时返回明确空状态（`empty_houses` 列出空宫；没有任何命中时 `layout` 为空数组，页面显示空状态），不补写推测。

### 5.2 组合式文案，而非逐组合穷举

行星解读天然是「星体 × 座 × 宫」的三元组合。若逐组合写文案需要 12×12 + 12×12 = 288 条，且难维护。本方案采用**组合式渲染 + 精修覆盖槽位**：

| 文案块 | 条目数 | 说明 |
| --- | --- | --- |
| `planet_core[point_id]` | 12 | 星体本体基义，不随座宫变化 |
| `sign_style[sign_id]` | 12 | 该座的表现方式（节奏、需求、表达），并携带中文 `label` |
| `house_field[house]` | 12 | 该宫的生活场景（领域、场合、关系） |
| `aspect_style[type]` | 6 | 相位性质（合、冲、刑、拱、六合、梅花） |
| `ascendant_sign[sign_id]` | 12 | 上升专项文案 |
| `sun_sign[sign_id]` / `moon_sign[sign_id]` | 24 | 太阳、月亮专项文案 |
| `house_ruler` | 12 | 宫主星去向的解释框架 |

基础文案合计约 90 条即可覆盖全盘。同时提供覆盖槽位：

```jsonc
"overrides": {
  "point_sign": { "sun:leo": "…" },           // 精修「太阳狮子」
  "point_house": { "moon:4": "…" },           // 精修「月亮4宫」
  "point_sign_house": { "venus:libra:7": "…" } // 精修整段
}
```

编辑可以只精修高价值组合（太阳、月亮、上升、命主星、强 stellium），其余走组合式，避免首期就背 288 条文案而质量参差。

### 5.3 组合的句式衔接

组合式最容易出现的问题是机械拼接（「你的太阳是……你的金牛座是……你的第9宫是……」）。因此每个槽位不只给一段文本，还给衔接信息：

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| `lead` | 引导词，决定句子怎么接上前一段 | 座：`表现为`；宫：`放在……这件事上` |
| `short` | 8-14 字短句，供概览条与卡片标题行复用 | `稳定、重实际` |
| `text` | 完整展开段 | `节奏偏慢，先确认安全感再投入。` |

约束：

- 一句话摘要按固定句式拼装，全卡只出现一次主语，不超过 40 字；
- 展开每段不超过 80 字，避免长段落；
- 统一使用「倾向 / 可能 / 适合留意」，不使用「你会 / 你就是 / 一定会」；
- 同一张卡内的三段共享语气与标点风格，避免一段口语一段书面。

### 5.4 卡片类型

| 卡片 | 事实来源 | 文案构成 |
| --- | --- | --- |
| 布局速读条 | §5.1 的统计结果 | 固定句式 + 数字 + 口径说明 |
| 三大核心（上升 / 太阳 / 月亮） | `angles.ascendant`、`points.sun`、`points.moon` | 专项文案 + 落宫场景 + 命主星 |
| 行星卡片（12 张） | `points[]` | 星体基义 + 座的表现 + 宫的场景（+ 逆行提示） |
| 十二宫卡片（12 张） | `houses[]` + 宫内 `points` | 宫位场景 + 宫头星座 + 宫主星落点 + 空宫状态 |
| 相位卡片 | `aspects[]`（按容许度排序） | 相位性质 + 两点基义 + 事实（容许度、入相/出相） |
| 分布概览 | `aggregates` | 元素 / 模式 / 宫位计数，纯事实描述 |
| 重点标记 | `derived_signals` | 角宫星体、逆行、强调元素/模式、星体群、紧密相位 |

### 5.5 相位措辞

传统「吉相位 / 凶相位」不直接作为结论。改用**流畅 / 张力**两轴描述，并保留事实：

- 拱、六合 → 顺畅、省力的连接；
- 刑、冲 → 需要协调的张力；
- 合 → 强度叠加，性质取决于参与的星体；
- 梅花 → 需要刻意调整的角度。

## 6. 规则与配置模型

### 6.1 布局统计与规则命中是两层

- **布局统计（`layout`）**：对 `structured` 的描述性统计，不是规则，不随配置版本变化而改变数值。即使 `natal_rules.json` 为空，`layout` 也必须完整可用。
- **规则命中（`signals`）**：`natal_rules.json` 里 `enabled` 的规则对统计值与派生信号的命名式命中，用于选择文案槽位与 observation code。

这样拆分的好处是：布局速读的准确性可以独立回归，文案与规则可以独立迭代。

### 6.2 事实层：`config/astro/natal_rules.json`

`schema_version` = `astro-natal-rules/1.0`。新增以下 `signal_type`（其余复用现有 C++ 派生信号）：

| signal_type | 粒度 | 证据字段 |
| --- | --- | --- |
| `point_in_sign` | 星体 × 座 | `point_id`、`sign_id`、`longitude`、`degree_in_sign` |
| `point_in_house` | 星体 × 宫 | `point_id`、`house`、`house_cusp`、`house_system` |
| `angle_in_sign` | 四轴 × 座 | `angle_id`、`sign_id`、`longitude` |
| `house_cusp_sign` | 宫 × 座 | `house`、`sign_id`、`cusp` |
| `house_ruler_placement` | 宫主星 | `house`、`ruler_id`、`ruler_house`、`ruler_sign_id` |
| `chart_ruler_placement` | 命主星 | `ruler_id`、`house`、`sign_id` |
| `hemisphere_stat` | 左/右、上/下 | `hemisphere`、`houses`、`count`、`total`、`ratio`、`point_ids` |
| `quadrant_stat` | 一/二/三/四象限 | `quadrant`、`houses`、`count`、`total`、`ratio`、`point_ids` |
| `sign_occupancy_stat` | 星座占据 | `sign_id`、`sign_name`、`count`、`total`、`ratio`、`point_ids` |
| `empty_house` | 空宫 | `house`、`sign_id`、`sign_name`、`cusp`、`house_system` |
| `aspect_network_stat` | 相位网络 | `total`、`harmony`、`tension`、`neutral`、`dominant`、`ratio`、`tight`、`mean_orb` |

`*_stat` 是**描述性统计信号**，本身不含「强调」判断；是否算强调由规则用 `match`、`min_count`、`min_ratio` 决定。规则既可以对 `hemisphere_stat` 用 `match {"hemisphere": "right"}` + `min_ratio: 0.6`，也可以对 `sign_occupancy_stat` 用 `min_count`，不需要为每种阈值新增信号类型。

每条规则至少包含：

- `rule_id`、`revision`、`enabled`；
- `signal_type` 与匹配阈值（`min_count` / `min_ratio` 等）；
- `dimension`（core / placement / field / layout / aspect / distribution）；
- 允许使用的文案槽位；
- `observation_code`、`boundary`：该规则不得越界的说明。

### 6.3 统计口径必须显式声明

半球、象限、星座与宫位占据**只统计十大行星**（太阳、月亮、水星、金星、火星、木星、土星、天王星、海王星、冥王星）中落宫有效的点位；真交点、凯龙等虚点仍出现在逐点位信号里，但不参与分布统计。这与常见星盘读法一致，也避免「换一个统计集合数字就变了」却无人察觉。

口径写进响应：

```jsonc
"hemispheres": {
  "definition": "半球、象限、星座与宫位占据只统计十大行星中落宫有效的点位；真交点、凯龙等虚点不参与分布统计。",
  "counted_point_ids": ["sun", "moon", "…"],
  "counted_point_names": ["太阳", "月亮", "…"],
  "counted_total": 10,
  "missing_point_ids": [],
  "items": [
    {"name": "left",  "houses": [1,2,3,10,11,12], "count": 7, "total": 10, "ratio": 0.7, "point_ids": ["…"]},
    {"name": "right", "houses": [4,5,6,7,8,9],   "count": 3, "total": 10, "ratio": 0.3, "point_ids": ["…"]},
    {"name": "above", "houses": [7,8,9,10,11,12], "count": 4, "total": 10, "ratio": 0.4, "point_ids": ["…"]},
    {"name": "below", "houses": [1,2,3,4,5,6],    "count": 6, "total": 10, "ratio": 0.6, "point_ids": ["…"]}
  ]
}
```

`counted_point_names` 与 `counted_point_ids` 成对返回，页面在普通模式下显示中文名，专业与研究模式下仍可按 ID 核对。

### 6.4 宫主星体系必须显式声明

宫主星卡片依赖主星体系。**已定：默认采用现代主星**（天蝎-冥王、水瓶-天王、双鱼-海王），并在响应中返回 `ruler_system: "modern"`；传统主星（天蝎-火星、水瓶-土星、双鱼-木星）作为可切换配置（请求传 `ruler_system: "traditional"`），不静默混用。

### 6.5 文案层：`config/astro/natal_reading_templates.json`

`schema_version` = `astro-natal-templates/1.0`。模板只按 `rule_id` / 槽位选择文案，输出带 `rule_id`、`revision`、`slot`、`text`。缺失槽位时返回明确空状态，不补写没有事实支持的结论。

```jsonc
{
```

## 9. 边界与禁止项

- 不使用「必然、注定、一定会」等确定性措辞，统一使用「倾向、可能、适合留意」；
- 布局（半球、象限、星体群、强调元素）只表示**结构集中度**，不表示性格定论或现实结果好坏；
- 不输出健康诊断、投资建议、法律判断和重大人生决定结论；
- 相位不直接判定吉凶，只描述顺畅 / 张力与需要协调的部分；
- 逆行不表述为负面事件，只描述为「向内、回看、重做」的表达倾向；
- 缺失规则时返回明确空状态，不用大模型补写未被事实支持的段落；
- 不做分数、不做领域排名、不做分享卡片上的断语；
- 不复制竞品文案、插画、图标与幸运物内容。

## 11. 验收标准

1. 同一星盘 + 同一配置版本 → 解读包完全一致，可作为回归 fixture；
2. 每张卡片至少带一个 `rule_id`、`revision` 和可核对证据；
3. 布局统计与手工核算一致，`counted_point_ids` / `counted_point_names` / `definition` 与实际统计集合一致，且左半 + 右半、上 + 下、四象限之和都等于 `counted_total`；
4. 375 / 768 / 1440 下无页面横向滚动（圆盘容器内滚动除外）；
5. 词表检查通过：无确定性断语、无健康/投资/法律结论；
6. 未覆盖组合在响应中显式列出，页面显示空状态而非臆造内容；
7. 圆盘与解读页签可双向跳转，键盘可达。
