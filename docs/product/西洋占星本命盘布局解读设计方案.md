# 西洋占星本命盘布局解读设计方案

> 前置方案：[西洋占星生活化解析设计方案](西洋占星生活化解析设计方案.md)（行运 / 日运链路 A0-A8）
> 本方案是与之并列的**本命盘静态解读**链路，编号 N1-N5。

## 1. 背景与目标

西洋占星页现在的「本命盘」页签已经把黄道、宫位、四轴、星体和相位画成了可读的圆盘，「结构事实」页签提供原始表格，「解析提示词」页签给出交给外部 AI 的结构化 JSON。也就是说**事实已经完备，缺的是页面内的解读层**。

本方案目标是增加一条「本命盘结构化事实 → 布局信号 → 可读解读卡片」的链路：

- 用户不复制提示词、不离开页面，就能看懂自己盘上的黄道与宫位布局；
- 每条解读都能回溯到星体、星座、宫位、黄经、相位容许度和配置版本；
- 解读是对结构化事实的表达，不改变排盘结果，也不引入新的事实；
- 普通模式易读，专业模式可核对，研究模式保留规则与未覆盖项。

参考「测测」一类产品星盘解读的**信息架构和阅读节奏**：先给上升 / 太阳 / 月亮三个核心，再按星体逐条展开落座落宫，然后补十二宫、相位与分布。本方案不复制竞品文案、插画或图标资产。

## 2. 竞品参考拆解

测测一类 App 的星盘解读大致遵循以下阅读顺序，本项目借鉴的是这个顺序本身：

1. 首屏三大核心（上升、太阳、月亮），一句话定性；
2. 按星体逐条展开「落在哪个座、落在第几宫」，每条配一段解读；
3. 十二宫位说明（宫头星座、宫内星体、宫主星去向）；
4. 相位解读（哪些点连在一起、意味着什么）；
5. 元素 / 模式分布概览（火土风水、基本固定变动）；
6. 专业信息折叠在二级层，普通用户默认不看到术语。

差异点：本项目把「每条解读可回溯到规则与证据」作为硬要求，不做无来源的断语，也不做分数化的吉凶排名。

## 3. 产品分层

| 模式 | 面向 | 内容 |
| --- | --- | --- |
| 普通模式 | 只想看懂盘的普通用户 | 三大核心卡、行星卡片一句话、展开后的三段解读、分布条；术语默认折叠 |
| 专业模式 | 会看盘的用户 | 黄经、度分、宫头、宫制、黄道、容许度、入相/出相、rule_id 与版本 |
| 研究模式 | 规则校准 | 全部派生信号、命中规则、未覆盖组合、文案映射与空状态 |

## 4. 可用的排盘事实（现状盘点）

`POST /api/v1/astro/charts` 返回的 `data.structured`（`astro-structured/1.0`）已经提供了解读所需的全部事实，**本方案不新增排盘计算**：

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| `points[]` | 12 点位：`longitude`、`degree_in_sign`、`sign_id`、`house`、`motion.retrograde`、`classification.element/modality` | 行星落座 / 落宫 / 逆行卡片 |
| `angles[]` | `ascendant`、`midheaven`、`descendant`、`imum_coeli` 的座与度 | 三轴卡片、四轴说明 |
| `houses[]` | 12 宫：`cusp`、`sign_id`、`sign_name`、`element`、`modality` | 十二宫卡片、宫头星座 |
| `aspects[]` | `source_id`、`target_id`、`type`、`orb`、`phase` | 相位卡片 |
| `aggregates` | `element_counts`、`modality_counts`、`house_counts` | 分布概览 |
| `derived_signals` | `angular_planet`、`retrograde_point`、`element_emphasis`、`modality_emphasis`、`sign_stellium`、`house_stellium`、`tight_aspect` | 重点标记，直接复用 |

因此事实层信号一律**从 `structured` 在 Python 侧派生**（`web/astro_natal_analysis.py`），不修改 C++ 排盘核心、不触发全量重建；这与行运链路的做法一致。

## 5. 解读内容架构

### 5.1 组合式文案，而非逐组合穷举

行星解读天然是「星体 × 座 × 宫」的三元组合。若逐组合写文案需要 12×12 + 12×12 = 288 条，且难维护。本方案采用**组合式渲染 + 精修覆盖槽位**：

| 文案块 | 条目数 | 说明 |
| --- | --- | --- |
| `planet_core[point_id]` | 12 | 星体本体基义，不随座宫变化 |
| `sign_style[sign_id]` | 12 | 该座的表现方式（节奏、需求、表达） |
| `house_field[house]` | 12 | 该宫的生活场景（领域、场合、关系） |
| `aspect_style[type]` | 6 | 相位性质（合、冲、刑、拱、六合、梅花） |
| `ascendant_sign[sign_id]` | 12 | 上升专项文案 |
| `sun_sign[sign_id]` / `moon_sign[sign_id]` | 24 | 太阳、月亮专项文案 |
| `house_ruler` | 12 | 宫主星去向的解释框架 |

基础文案合计约 90 条即可覆盖全盘。同时提供覆盖槽位：

```jsonc
"overrides": {
  "point_sign": { "sun:leo": "…" },        // 精修「太阳狮子」
  "point_house": { "moon:4": "…" },        // 精修「月亮4宫」
  "point_sign_house": { "venus:libra:7": "…" } // 精修整段
}
```

编辑可以只精修高价值组合（太阳、月亮、上升、命主星、强stellium），其余走组合式，避免首期就背 288 条文案而质量参差。

### 5.2 组合的句式衔接

组合式最容易出现的问题是机械拼接（「你的太阳是……你的金牛座是……你的第9宫是……」）。因此每个槽位不只给一段文本，还给衔接信息：

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| `lead` | 引导词，决定句子怎么接上前一段 | 座：`表现为`；宫：`放在……这件事上` |
| `short` | 8-14 字短句，供概览条与卡片标题行复用 | `稳定、重实际` |
| `text` | 完整展开段 | `节奏偏慢，先确认安全感再投入。` |

约束：

- 一句话摘要按固定句式拼装，全卡只出现一次主语，不超过 40 字；
- 展开每段不超过 80 字，避免长段落；
- 统一使用「倾向 / 可能 / 适合留意」，不使用「你会 / 你就是 / 一定会」；
- 同一张卡内的三段共享语气与标点风格，避免一段口语一段书面。

### 5.3 卡片类型

| 卡片 | 事实来源 | 文案构成 |
| --- | --- | --- |
| 三大核心（上升 / 太阳 / 月亮） | `angles.ascendant`、`points.sun`、`points.moon` | 专项文案 + 落宫场景 + 命主星 |
| 行星卡片（12 张） | `points[]` | 星体基义 + 座的表现 + 宫的场景（+ 逆行提示） |
| 十二宫卡片（12 张） | `houses[]` + 宫内 `points` | 宫位场景 + 宫头星座 + 宫主星落点 |
| 相位卡片 | `aspects[]`（按容许度排序） | 相位性质 + 两点基义 + 事实（容许度、入相/出相） |
| 分布概览 | `aggregates` | 元素 / 模式 / 宫位计数，纯事实描述 |
| 重点标记 | `derived_signals` | 角宫星体、逆行、强调元素/模式、星体群、紧密相位 |

### 5.4 相位措辞

传统「吉相位 / 凶相位」不直接作为结论。改用**流畅 / 张力**两轴描述，并保留事实：

- 拱、六合 → 顺畅、省力的连接；
- 刑、冲 → 需要协调的张力；
- 合 → 强度叠加，性质取决于参与的星体；
- 梅花 → 需要刻意调整的角度。

## 6. 规则与配置模型

### 6.1 事实层：`config/astro/natal_rules.json`

新增以下 `signal_type`（其余复用现有信号）：

| signal_type | 粒度 | 证据字段 |
| --- | --- | --- |
| `point_in_sign` | 星体 × 座 | `point_id`、`sign_id`、`longitude`、`degree_in_sign` |
| `point_in_house` | 星体 × 宫 | `point_id`、`house`、`house_cusp`、`house_system` |
| `angle_in_sign` | 四轴 × 座 | `angle_id`、`sign_id`、`longitude` |
| `house_cusp_sign` | 宫 × 座 | `house`、`sign_id`、`cusp` |
| `house_ruler_placement` | 宫主星 | `house`、`ruler_id`、`ruler_house`、`ruler_sign_id` |
| `chart_ruler_placement` | 命主星 | `ruler_id`、`house`、`sign_id` |

每条规则至少包含：

- `rule_id`、`revision`、`enabled`；
- `signal_type` 与匹配阈值；
- `dimension`（core / placement / field / aspect / distribution）；
- 允许使用的文案槽位；
- `boundary`：该规则不得越界的说明。

### 6.2 宫主星体系必须显式声明

宫主星卡片依赖主星体系。默认采用**现代主星**（天蝎-冥王、水瓶-天王、双鱼-海王），并在响应中返回 `ruler_system: "modern"`；传统主星（天蝎-火星、水瓶-土星、双鱼-木星）作为可切换配置，不静默混用。

### 6.3 文案层：`config/astro/natal_reading_templates.json`

模板只按 `rule_id` / 槽位选择文案，输出带 `rule_id`、`revision`、`slot`、`text`。缺失槽位时返回明确空状态，不补写没有事实支持的结论。

```jsonc
{
  "schema_version": "astro-natal-templates/1.0",
  "planet_core": {
    "sun":  {"revision": 1, "title": "核心意志", "short": "想要被看见的部分",
             "text": "太阳代表核心意志、想要成为的样子，以及最需要被认可的部分。"}
  },
  "sign_style": {
    "taurus": {"revision": 1, "lead": "表现为", "short": "稳定、重实际",
               "text": "节奏偏慢，先确认安全感，再决定投入多少。"}
  },
  "house_field": {
    "9": {"revision": 1, "lead": "放在", "short": "远方与高等学习",
          "text": "远行、高等教育、信念体系与跨文化经验，是需要拉长时间看的那一块。"}
  },
  "summary": {
    "point": "{planet_title}落在{sign_name}{house_ordinal}宫：{sign_short}，重心放在{house_short}。"
  },
  "overrides": {
    "point_sign":  {"sun:leo": {"revision": 1, "text": "……"}},
    "point_house": {"moon:4":  {"revision": 1, "text": "……"}}
  }
}
```

`summary.point` 是唯一的摘要句式，避免每个槽位各自拼一句话导致语气不一致。

### 7.3 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/astro/natal-analysis` | 输入 `chart`，输出事实 + 规则命中包 |
| POST | `/api/v1/astro/natal-reading` | 输入 `chart`（自动先跑分析）或直接传 `analysis`，输出解读包 |

`/natal-reading` 与既有 `/daily-reading` 保持同构：页面只需调用一次。

## 8. 页面方案

### 8.1 页签结构

二级页签由「本命盘 / 结构事实 / 解析提示词」调整为：

```text
本命盘       圆盘（已完成）
本命解读     新增：三大核心 + 行星卡片 + 十二宫 + 相位 + 分布
结构事实     原始表格（保留）
解析提示词   外部 AI 用（保留）
```

### 8.2 「本命解读」页签布局

```text
概览条：上升 / 太阳 / 月亮（座 + 宫 + 一句话） + 命主星
分布条：火土风水计数、基本固定变动计数、宫位分布
排序切换：按星体 / 按宫位 / 按星座
行星卡片：12 张（折叠，标题行 + 一句话，展开三段 + 证据 + 重点标记）
十二宫卡片：12 张（宫头星座、宫内星体、宫主星落点）
主要相位：按容许度排序，软硬分级
阅读边界：事实与推断的边界说明
```

### 8.3 与圆盘联动

圆盘上的星体已经可聚焦（`g.planet` 带 `tabindex`）。新增：

- 点击 / 回车圆盘星体 → 切到「本命解读」页签并滚动高亮对应卡片；
- 卡片内「在圆盘上查看」→ 切回「本命盘」页签并高亮该星体；
- 键盘路径：圆盘星体 → Tab 到卡片 → 展开证据，全程可用。

### 8.4 卡片解剖

```text
[符号] 太阳 · 金牛座 · 第9宫          [重点：太阳-月亮六合 0.72°]
一句话：把稳定的价值感用在远方与高等学习上。
── 展开 ──────────────────────────────
星体基义：太阳代表核心意志与想要被看见的部分。
金牛座的表现：节奏偏慢、重实际、先确认安全感再投入。
第9宫的场景：远行、高等教育、信念体系与跨文化经验。
证据：黄经 58.9724°、座内 28.97°、第9宫（Placidus，宫头 57.2514°）
      rule: point_in_sign:sun:taurus / point_in_house:sun:9
```

## 9. 边界与禁止项

- 不使用「必然、注定、一定会」等确定性措辞，统一使用「倾向、可能、适合留意」；
- 不输出健康诊断、投资建议、法律判断和重大人生决定结论；
- 相位不直接判定吉凶，只描述顺畅 / 张力与需要协调的部分；
- 逆行不表述为负面事件，只描述为「向内、回看、重做」的表达倾向；
- 星体群、强调元素、角宫星体等「重点」只表示**结构集中度**，不表示现实结果好坏；
- 缺失规则时返回明确空状态，不用大模型补写未被事实支持的段落；
- 不做分数、不做领域排名、不做分享卡片上的断语。

| 迭代 | 主题 | 主要交付物 | 验收重点 |
| --- | --- | --- | --- |
| N1 | 事实层与信号契约 | `config/astro/natal_rules.json`、`web/astro_natal_analysis.py`、`POST /natal-analysis`、`astro-natal-analysis/1.0` | 每个信号可回溯到星体、座、宫、黄经与宫制 |
| N2 | 组合文案层 | `config/astro/natal_reading_templates.json`、`web/astro_natal_reading.py`、`POST /natal-reading`、`astro-natal-reading/1.0` | 组合式拼装 + override 槽位；无配置时明确空状态 |
| N3 | 页面 MVP | 新增「本命解读」页签、三大核心卡、行星卡片、分布条、圆盘联动 | 375 / 768 / 1440 可用，卡片可展开证据 |
| N4 | 重点精修 | 上升/太阳/月亮专项文案、重点组合 override、命主星与宫主星卡 | 首屏 3 秒可读，语感达到可用水准 |
| N5 | 规则校准与发布 | 固定案例集、人工评审、版本与回退说明 | 文案不越界，同盘同版本输出稳定 |

## 11. 验收标准

1. 同一星盘 + 同一配置版本 → 解读包完全一致，可作为回归 fixture；
2. 每张卡片至少带一个 `rule_id`、`revision` 和可核对证据；
3. 375 / 768 / 1440 下无页面横向滚动（圆盘容器内滚动除外）；
4. 词表检查通过：无确定性断语、无健康/投资/法律结论；
5. 未覆盖组合在响应中显式列出，页面显示空状态而非臆造内容；
6. 圆盘与解读页签可双向跳转，键盘可达。

## 12. 暂不做

- 不做合盘、行运、推运解读（行运已有独立方案）；
- 不引入大模型生成数据层文案；
- 不做分数、排名与吉凶评级；
- 不复制竞品文案、插画、图标与幸运物内容；
- 首期不做流年时间线、事件预测与提醒推送。
