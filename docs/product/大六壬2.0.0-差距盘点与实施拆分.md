## 2. 逐条差距

### DLR-201 输入与时间
- ❌ 一键当前时间、示例时间；提交期间按钮禁用 + 计算状态
- ❌ 农历闰月勾选（引擎已原生支持 `leap_month`，仅缺前端入口，见 §4.1）
- ⚠️ 时间口径说明现仅一句；需明示时区(本地输入无时区语义)、子时换日、月将切换依据、分钟不参与
- ✅ 非法日期错误透传（引擎 `INVALID_ARGUMENT` → 422）

### DLR-202 问题上下文
- ❌ 全部：问题类型（感情/工作/财运/出行/健康/其他）+ 可选描述 + 结果页保留上下文
- 约束：描述**不进服务端**（仅前端会话内展示，天然满足"不写入服务日志"）

### DLR-203 双模式结果
- ❌ 小白/专业模式切换（同一份数据，零重复请求）
- 小白视图素材映射（全部来自既有字段，零新增算法）：
  - 八字/月将/贵人 → `ba_zi`,`yue_jiang`,`gui_ren`
  - 本课重点 → `san_chuan.ke_shi`(课式名) + `gua_ti` 的**结构化展示**（不做吉凶断语）
  - 三传流程 → `details[].stage` 渲染为 起因→发展→结果 三步卡
  - 基础说明 → 术语帮助内联链接
- 专业视图 = 现有内容升级：四课、三传详情、天地盘 12 位表格、神将、遁干、六亲、旬空、神煞分组、卦体

### DLR-204 术语帮助
- ❌ 全部：四课/三传/初传/中传/末传/月将/贵人/课式/六亲/旬空 十词解释，**每条标注当前口径**
- 落位：`config/daliuren/glossary.json`（声明式，平台规则配置惯例），页面弹层渲染；键盘 + 移动端可达

### DLR-205 接口契约
- ✅ 既有字段保持；新字段只做向后兼容新增
- ❌ 规则口径标识：引擎输出追加 `meta.rule_profile`（月将取法、三传取法、课式体系、子时口径），server 统一包 `meta` 已含 `algorithm_version`
- ⚠️ 六壬 CLI 当前按小时起课（分钟不下传），与说明一致；2.0.0 不改

### 非功能
- ⚠️ 375/768/1440 无横向滚动、键盘链路、44px 触控：沿用 `divination.css/app-shell.css` 体系，改版后需专项核对
- ✅ 起课响应 <3s：现状 CLI 单次 ~50ms

### 完成定义
- ❌ `tests/test_da_liu_ren_web_contract.py`（静态契约）+ CLI 输出行为测试（闰月、错误码、rule_profile）
- ❌ README/接口文档/页面文案同步；发布说明记录已知口径与未解决问题（算法仍 pending 校准）

## 4. 风险与决策点

1. **闰月**：✅ 已核实（2026-09-18）：`da_liu_ren_web_cli` 已支持 `leap_month`（负数月约定，与奇门一致），I1 无需为此动引擎；I3 前端加勾选即可。
2. **rule_profile 口径措辞**：需从 `docs/大六壬起课-步骤.md`/`大六壬怎么学.md` 提炼并逐条对照代码实现，写错口径比不写更伤可信度——I1 提交前需人工确认。
3. **小白模式"本课重点"**：只允许结构化转译（课式名、卦体名、三传 stage），不得出现吉凶断语，符合"明确不做"清单。
