# ZhouYiLab 2.0.0 产品规划头脑风暴

## 产品定位

ZhouYiLab 不只是排盘网页，而是一个可验证、可解释、可追溯的中国传统术数实验室。

目标用户分为三层：

1. 想快速完成一次排盘的普通用户。
2. 想理解盘面和学习术数的初学者。
3. 想校准规则、比较门派和研究算法的专业用户与开发者。

## 产品原则

- 先展示排盘事实，再展示规则解释，最后才提供趋势性判断。
- 小白模式和专业模式分层，默认让用户容易完成任务。
- 每个算法都记录当前口径、来源、校准状态和版本。
- 不把单一神煞或单一符号直接包装成确定的现实结论。
- 每个版本都应可运行、可验证、可部署、可回退。

## 大六壬方向

大六壬优先建设为第一个完整的“事实 + 解释”产品：

- 输入起课时间、历法和用户问题。
- 输出八字、月将、贵人、四课、三传、天地盘、神将、遁干、六亲、神煞和卦体。
- 用三传流程表达“起因、发展、结果”，降低术语门槛。
- 提供术语解释、看盘顺序和当前门派口径。
- 专业模式展示完整盘面和结构化 JSON。

## 分层体验

### 快速使用层

- 问题类型：感情、工作、财运、出行、健康、其他。
- 可选问题描述，例如“这次面试能否通过？”。
- 一键使用当前时间和示例排盘。
- 顶部显示本课重点，而不是只显示原始字段。

### 学习理解层

- 四课、三传使用流程化布局。
- 天地盘使用十二宫盘面表示。
- 初传、中传、末传分别标注起因、发展、结果。
- 月将、贵人、课式、六亲、旬空和神煞提供解释。
- 默认折叠神煞，支持查看完整内容。

### 研究校准层

- 显示算法版本、规则口径和资料来源。
- 建立元首、重审、比用、涉害、遥克、昴星、别责、八专、伏吟、返吟案例。
- 支持参考结果、当前结果和差异报告。
- 支持不同门派或规则配置的结果比较。

## 版本拆解

### 2.0.0：大六壬可交付基础版

- 小白模式和专业模式。
- 问题类型与问题描述输入。
- 三传流程展示和本课重点摘要。
- 农历闰月输入。
- 时间口径说明：标准时间、子时换日、月将切换规则。
- 大六壬术语帮助和看盘顺序。
- 当前排盘字段的结构化 API 契约。

验收标准：新用户无需阅读专业文档即可完成一次起课，并能解释三传分别代表什么。

### 2.1.0：天地盘可视化版

- 十二宫天地盘。
- 天盘、地盘、神将、日干寄宫、日支、月将和三传落宫标记。
- 移动端可读布局。
- 盘面事实与文本摘要同步。

验收标准：专业用户能从盘面直接核对四课和三传取用位置。

### 2.2.0：规则解释版

- 课式规则说明。
- 四课生克关系可视化。
- 三传取法过程追踪。
- 神煞分组、折叠和来源链接。
- 解释内容明确区分事实、规则和趋势。

验收标准：每个主要结论都能回溯到具体盘面字段和规则。

### 2.3.0：案例校准版

- 大六壬标准案例库。
- 算法回归测试。
- 边界时间测试。
- 不同规则口径的差异报告。
- 页面显示校准状态。

验收标准：每次算法修改都能自动发现已知案例结果变化。

### 2.4.0：跨术数统一版

- 统一历法、时区、真太阳时和子时处理说明。
- 紫微、奇门、八字、六爻、大六壬统一案例输入格式。
- 跨算法结果并列查看。
- 统一 API 元数据和版本标识。

验收标准：同一时间输入在不同术数页面的时间口径透明且可追踪。

## 平台能力

- C++ 负责可测试的核心计算。
- CLI 输出稳定 JSON，Web 只负责交互和展示。
- 每个算法拥有独立的规则文档、案例和回归测试。
- Docker 镜像和 Compose 文件作为标准部署方式。
- 版本发布必须包含源码、测试、容器和变更说明。

## 暂不做的事情

- 不在算法尚未校准前大量增加自动断语。
- 不让 AI 直接决定排盘事实。
- 不为了视觉效果牺牲盘面字段的可核对性。
- 不同时推进过多新术数，优先把大六壬做成完整样板。
