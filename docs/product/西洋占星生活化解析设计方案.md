# 西洋占星生活化解析设计方案

## 1. 背景与目标

当前西洋占星模块已经能够生成本命盘，并返回行星、角度、宫位、相位、结构化字段和可复核的派生信号。页面仍以专业排盘和复制 AI 提示词为主，缺少普通用户可以每天消费的时间性内容。

本方案参考“测测”一类产品的日运体验，目标是增加一条“本命盘 + 指定日期行运 → 生活领域信号 → 生活化解析卡片”的产品链路：

- 用户可以查看今天或一段时间内的生活提示；
- 每条提示都能回溯到行运、宫位、相位和规则版本；
- 生活化文案是对结构化信号的表达，不改变排盘事实；
- 普通模式易读，专业模式可核对，研究模式保留规则和证据。

本方案不把占星内容包装成确定性事件预测，也不把分数解释为现实结果概率。

## 2. 竞品参考拆解

截图所体现的主要交互结构是：

1. 日、周、月、年四种时间范围。
2. 日期横向浏览，并突出今天。
3. 综合反馈和爱情、财富、事业、学习、人际等分领域反馈。
4. 一段带有情绪和场景的今日总结。
5. 一个重点领域提醒，以及建议和避免事项。
6. 幸运色、时段、数字、食物等轻量附加信息。

本项目借鉴的是信息架构和阅读节奏，不直接复制品牌文案、视觉资产或未经验证的断语。

## 3. 产品分层

### 3.1 普通模式

面向只想知道“今天适合关注什么”的用户。首屏依次显示日期、总体状态、四到五个生活领域、今日摘要、重点提醒、建议和避免事项。专业术语默认折叠。

### 3.2 专业模式

展示本命盘与行运盘的计算口径、具体行星、宫位、相位、容许度、入相/出相、规则 ID 和信号证据。普通模式的每一张卡片都应能跳转到对应证据。

### 3.3 研究模式

用于规则校准和版本比较，显示原始事实、规则命中、文案映射、版本和未配置内容。不生成不可追溯的综合结论。

## 4. 数据与计算模型

### 4.1 输入

- 已保存或本次提交的本命盘请求；
- 目标日期、当地时间、时区和地点；
- 黄道体系和宫制；
- 行运计算的点位范围；
- 可选的时间范围：day、week、month、year。

### 4.2 首期行运点位

首期只纳入太阳、月亮、水星、金星和火星。它们对日常情绪、沟通、关系、行动和短期节奏的变化更适合做第一轮验证。木星、土星、天王星、海王星、冥王星和凯龙星保留为后续扩展，不在首期混入评分。

### 4.3 行运事实包

事实包只描述计算结果，不描述吉凶：

- 行运行星的黄经、星座、宫位和速度；
- 行运行星与本命太阳、月亮、上升、个人行星的主要相位；
- 相位类型、容许度、入相/出相和计算时刻；
- 月亮当天的换座和主要相位时间；
- 本命盘和行运计算使用的黄道、宫制、星历来源和警告。

推荐新增稳定结构版本：`astro-transit-structured/1.0`。

### 4.4 生活领域映射

首期领域固定为：感情、财富、事业、学习、人际。映射规则必须配置化，不能散落在前端文案中。

| 领域 | 首期关注的宫位 | 首期关注的点位/信号 | 输出方向 |
| --- | --- | --- | --- |
| 感情 | 5、7、8 | 月亮、金星、火星及与本命个人点位的相位 | 交流、亲密感、边界、冲突 |
| 财富 | 2、8 | 金星、木星（后续）、土星（后续） | 消费、预算、共享资源 |
| 事业 | 6、10 | 太阳、火星、土星（后续） | 任务、执行、责任、优先级 |
| 学习 | 3、9 | 水星、月亮及紧密相位 | 注意力、信息处理、复习 |
| 人际 | 7、11 | 金星、月亮、天王星（后续） | 协作、社交、距离感 |

同一个事实可以映射到多个领域，但每个领域都必须保留自己的证据列表，不能只返回一个无法解释的总分。

## 5. 解析输出契约

推荐新增 `astro-daily-reading/1.0`，示例结构如下：

```json
{
  "date": "2026-09-17",
  "scope": "day",
  "overall": {
    "label": "适合收拢注意力的一天",
    "index": null,
    "index_semantics": "可选的规则关注度，不是事件概率"
  },
  "dimensions": {
    "love": {"index": null, "label": "有交流机会", "signal_ids": []},
    "wealth": {"index": null, "label": "先控制冲动消费", "signal_ids": []},
    "career": {"index": null, "label": "任务容易堆积", "signal_ids": []},
    "learning": {"index": null, "label": "适合短时专注", "signal_ids": []},
    "social": {"index": null, "label": "保持边界感", "signal_ids": []}
  },
  "summary": "今天可能会觉得事情同时找上门，先处理最明确的一件，节奏会慢慢稳定下来。",
  "focus": {
    "dimension": "career",
    "title": "事业提醒",
    "text": "工作上容易突然出现待处理的事项，先列出优先级，再逐项推进。",
    "signal_ids": []
  },
  "actions": ["列出今天最重要的三个步骤"],
  "avoid": ["在疲惫时反复修改已经完成的决定"],
  "lucky": {},
  "evidence": [],
  "versions": {
    "transit_schema": "astro-transit-structured/1.0",
    "reading_schema": "astro-daily-reading/1.0",
    "rules": "astro-rules/1.0"
  }
}
```

`index` 只有在评分规则经过单独校准后才启用。首期可以先返回标签和信号强度，页面暂时显示“关注度”或等级，不应暗示成功率、财富金额、健康结论或必然事件。

## 6. 规则与文案层

规则层负责把行运事实转换为稳定信号，例如 `transit_mars_square_natal_mercury`、`moon_in_natal_6th_house`。文案层负责把信号填入有限的模板槽位：摘要、重点提醒、建议、避免事项。

每条规则至少包含：

- `rule_id`、`revision`、适用范围；
- 输入信号类型和阈值；
- 目标生活领域；
- 方向、强度和置信级别；
- 允许使用的文案模板；
- 证据字段和边界说明。

文案使用“可能、适合、可以留意、建议”这类条件性表达。健康、法律、投资和重大人生决定不输出诊断、保证或具体结果。

## 7. 页面方案

### 7.1 日运首屏

```text
时间范围：日 / 周 / 月 / 年
日期选择：前一天 / 今天 / 后一天
总体状态：标签 + 可选关注度
领域卡片：感情 / 财富 / 事业 / 学习 / 人际
今日摘要
重点领域提醒
建议 / 避免
幸运信息（规则稳定后再启用）
```

### 7.2 详情展开

每个领域展开后显示“为什么这样提示”：行运点位、相位、宫位、容许度、规则版本和不确定性。专业模式继续保留完整星盘圆盘和结构化 JSON。

### 7.3 时间范围策略

- 日：显示月亮和个人行星的短期变化；
- 周：聚合每天的主要信号，显示持续时间和峰值；
- 月：显示慢行星和重要转折，减少逐日文案；
- 年：只做趋势摘要，不复制日运卡片。

## 9. A1 实施范围记录

A1 的最小范围是：

1. 明确行运请求字段和响应字段；
2. 复用现有 Swiss Ephemeris 能力计算指定时刻的行运点位；
3. 计算行运点位与本命核心点位的主要相位；
4. 输出稳定的事实包和版本信息；
5. 增加固定日期、时区、边界角度和星历降级测试；
6. 补充接口文档和一个可供后续规则使用的 JSON fixture。

A1 已完成：行运接口、事实包、固定 fixture、时区继承、宫位归属、星历降级和错误边界均已加入回归测试。A2、A3 已在此事实包之上完成规则和无评分模板层，下一步进入 A4。没有稳定的行运事实包，后续生活化文案无法验证。

## 10. A2 已交付：生活领域信号规则

A2 新增 `config/astro/transit_rules.json` 和 `POST /api/v1/astro/transit-analysis`。接口接受已有的 A1 行运事实包，或接受 `transit_request` 由服务先调用行运引擎；也可以用 `scope` 或 `dimensions` 限定生活领域。

分析版本为 `astro-transit-analysis/1.0`，规则版本为 `astro-transit-rules/1.0`。首批规则覆盖感情、财富、事业、学习、人际两类事实映射：行运行星落入本命宫位，以及行运行星与本命点位的主要相位。每个信号都返回 `signal_id`、`rule_id`、`revision`、方向、强度、观察代码、点位、A1 证据和边界说明。

A2 不生成摘要、建议、避免事项、幸运信息或分数；财富规则也不提供投资、借贷和金额建议。接口响应保留 `astro-transit-structured/1.0` 和本命 `astro-structured/1.0` 的来源版本，便于后续 A3 文案层追溯。

## 11. A3 已交付：无评分日运解析包

A3 新增 `config/astro/daily_reading_templates.json`、`web/astro_daily_reading.py` 和 `POST /api/v1/astro/daily-reading`。接口支持直接传入 A2 `analysis`，或传入 A1 `chart` / `transit_request` 后自动完成 A2 分析。

解析版本为 `astro-daily-reading/1.0`，模板版本为 `astro-daily-templates/1.0`。输出固定包含日期、日范围、总体标签、五个生活领域卡片、摘要、重点提醒、建议、避免、空幸运信息和证据列表；关注度 `index` 保留为 `null`，不计算分数。

模板只按 `rule_id` 选择文案，领域卡片和重点提醒保留命中的 `signal_id`，顶层 `evidence` 透传 A2 的规则、点位、事实证据和边界。没有命中规则时返回明确空状态，不补写未被事实支持的生活结论。A4 将在此解析包之上实现日期切换和证据展开页面。

## 12. 暂不做

- 不直接复制竞品的具体句式、插画或幸运物内容；
- 不让大模型重新计算星盘或修改行运事实；
- 不在首期输出健康诊断、投资建议、法律判断或确定性事件；
- 不把综合分数作为现实结果概率；
- 不在 A1 阶段同时实现周、月、年全部页面。
