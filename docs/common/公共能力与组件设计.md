# 公共能力与组件设计

> 维护日期：2026-09-15

公共 C++ 和 HTTP 接口详见[公共日历 API](./公共日历API.md)。

本文记录 ZhouYiLab 各术数模块之间已经确认的公共能力、组件边界和复用方式。公共能力只放稳定的基础数据、输入约束和历法适配；排盘规则、象意解释和具体输出契约仍由各功能模块负责。

## 1. 能力盘点

| 公共能力 | 当前使用模块 | 统一前的问题 | 统一后的组件 |
| --- | --- | --- | --- |
| 公历日期合法性 | 八字 Web CLI、六爻 Web CLI、奇门 Web CLI、紫微 Web CLI、西洋占星 | 闰年、月份和时间范围在多个入口重复判断，规则容易漂移 | `ZhouYi.Common.DateTime` |
| 农历输入范围 | 八字、六爻、奇门、紫微入口 | 负数闰月、月份和时分的边界判断分散 | `ZhouYi.Common.DateTime::is_valid_lunar_date` |
| 日期时间格式化 | 紫微命盘、紫微控制器、紫微/八字 Web CLI | 相同的 `YYYY-MM-DD HH:mm:ss` 格式重复实现 | `ZhouYi.Common.DateTime::format` |
| 民用时间与 tyme 转换 | 八字、奇门、大六壬、紫微 | `SolarTime`、`LunarHour` 构造调用散落在业务代码中 | `ZhouYi.Common.Calendar` |
| 公历/农历值对象互转 | 各排盘入口和公共调用方 | 只能通过 `tyme` 对象间接转换，闰月表示容易不一致 | `solar_to_lunar` / `lunar_to_solar` |
| 从时间获取八字 | 八字、奇门、紫微 | `get_lunar_hour().get_eight_char()` 重复出现 | `eight_char_from_solar_time` / `eight_char_from_lunar_time` |
| 真太阳时校正 | 紫微、八字及其他需要按经度校时的调用方 | 算法和参数校验绑定在紫微出生时间模块 | `correct_solar_time` / `calculate_true_solar_time` |
| 干支中文解析 | `Pillar`、八字/六爻/大六壬等 | `Pillar` 内部重复维护天干、地支字符串表 | `GanZhi::Mapper::from_zh_gan/from_zh_zhi` |
| 五行、干支关系 | 八字、六爻、大六壬、紫微 | 规则与术数语义耦合程度较高 | 暂留在 `GanZhi`、`WuXingUtils` 和各功能模块 |

## 2. 公共组件

### `ZhouYi.Common.DateTime`

文件：`src/common/calendar/date_time.cppm`

职责：

- 提供 `SolarDateTime` 和 `LunarDateTime` 两个无时区值对象。
- 提供公历闰年、月份天数、年内日序和日期时间合法性判断。
- 统一提供 `YYYY-MM-DD HH:mm:ss` 格式化。
- 农历月份使用负数表示闰月，与 `tyme4cpp` 的现有输入约定保持一致。

该组件不负责时区、节气或农历实际月长计算。实际历法规则交给 `tyme4cpp`，这样可以避免公共层复制历法数据。

### `ZhouYi.Common.Calendar`

文件：`src/common/calendar/calendar.cppm`

职责：

- `to_solar_time(SolarDateTime)`：构造 `tyme::SolarTime`。
- `to_lunar_hour(LunarDateTime)`：构造 `tyme::LunarHour`。
- `solar_to_lunar(SolarDateTime)`：公历值对象转换为农历值对象。
- `lunar_to_solar(LunarDateTime)`：农历值对象转换为公历值对象。
- `from_solar_time` / `from_lunar_time`：将 `tyme` 时间对象转换为公共值对象。
- `correct_solar_time`：按模式计算标准时间或真太阳时，并返回完整校正明细。
- `calculate_true_solar_time`：直接计算真太阳时的便捷 API。
- `calculate_equation_of_time_seconds`：计算均时差，单位为秒。
- `eight_char_from_solar_time` / `eight_char_from_lunar_time`：统一八字提取流程。

依赖方向为：

```text
ZhouYi.Common.DateTime  <-  ZhouYi.Common.Calendar  <-  功能模块
                                  |
                              ZhouYi.tyme
```

公共组件不依赖八字、奇门、紫微或大六壬功能模块，避免反向依赖和循环依赖。

## 3. 已完成的代码抽取

本次抽取已覆盖以下调用链：

1. `BaZiBase::BaZi::from_solar/from_lunar` 使用公共八字提取函数。
2. 奇门公历/农历排盘使用公共日期对象、`tyme` 构造和八字提取函数。
3. 大六壬公历/农历入口使用公共历法适配函数。
4. 公历/农历公共值对象互转统一使用 `solar_to_lunar` / `lunar_to_solar`，闰月以负数月份保留。
5. 真太阳时算法、均时差、经度校正、夏令时校正和跨日处理统一使用 `ZhouYi.Common.Calendar`。
6. 紫微真太阳时模块仅保留兼容类型别名和 `correct_birth_time` 转发。
7. 西洋占星使用公共公历日期时间校验，移除自身的闰年和月份天数实现。
8. 紫微与八字 Web CLI 复用公共日期格式化和日期校验。
9. `Pillar` 的干支中文解析复用 `GanZhi::Mapper`，删除重复的字符串哈希表。

紫微原有的 `ZhouYi::ZiWei::BirthDateTime` 保留为 `ZhouYi::Common::SolarDateTime` 的别名，因此现有示例和外部调用代码无需立即迁移。

## 4. 不抽取的边界

以下代码目前不属于公共组件：

- 八字的大运、流年、十神和神煞规则。
- 奇门的节气、局数、九宫和转盘规则。
- 大六壬的月将、四课、三传和课体规则。
- 紫微的宫位、安星、四化、运限和格局引擎。
- 西洋占星的黄道、宫制、相位和 Swiss Ephemeris 计算。
- 各 Web CLI 的 JSON 字段组织、错误码和页面专用输出。

这些能力虽然可能在概念上相似，但输入语义、校准口径或输出契约不同，继续放在各自功能层更容易保证算法独立性。

## 5. 使用约定

新功能需要日期输入时，优先使用：

```cpp
import ZhouYi.Common.Calendar;

const ZhouYi::Common::SolarDateTime birth{1990, 5, 20, 14, 30, 0};
if (!ZhouYi::Common::DateTime::is_valid_solar_date_time(birth)) {
    // 由调用层转换为自己的错误契约
}
auto solar_time = ZhouYi::Common::Calendar::to_solar_time(birth);
auto eight_char = ZhouYi::Common::Calendar::eight_char_from_solar_time(solar_time);

const auto lunar = ZhouYi::Common::Calendar::solar_to_lunar(birth);
const auto solar = ZhouYi::Common::Calendar::lunar_to_solar(lunar);
const auto corrected = ZhouYi::Common::Calendar::calculate_true_solar_time(
    birth,
    ZhouYi::Common::Calendar::TrueSolarTimeOptions{.longitude = 104.066});
```

调用层仍然负责把校验失败转换为 `std::expected`、异常或 HTTP JSON 错误；公共组件不绑定某一个接口层的错误协议。

## 6. 后续维护规则

- 先在本文登记跨两个以上功能模块的重复能力，再决定是否抽取。
- 公共组件只能依赖更底层的公共组件、`tyme` 或第三方库，不能依赖功能模块。
- 抽取时保留旧的对外类型名或函数签名，除非有明确的版本迁移计划。
- 公共 API 的农历月份用正数表示普通月、负数表示闰月；实际不存在的闰月由 `tyme4cpp` 校验并抛出异常。
- 真太阳时 API 使用显式经度和标准经线，返回 `SolarTimeCorrection`，调用方可直接取得标准时间、校正时间、各项秒数和是否跨日。
- 每次公共组件变更至少验证一次核心库构建，并回归受影响的 Web CLI。
- 需要术数规则知识才能解释的代码，不因为“看起来通用”就放进 `common`。
