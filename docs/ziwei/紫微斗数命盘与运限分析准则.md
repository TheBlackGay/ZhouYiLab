# 紫微斗数命盘与运限分析准则

> 状态：第一版基线
> 适用范围：ZhouYiLab 紫微斗数命盘解读、格局判断与运限分析
> 配套配置：`config/ziwei/analysis_cases.json`
> 象义词典：`config/ziwei/symbolism_dictionary.json`
> 研究协议：`docs/ziwei/research/紫微斗数星曜作用模型研究协议-v0.1.md`

## 1. 目的

本文件是项目实现紫微斗数解读功能时必须遵循的分析准则。排盘负责给出可验证的宫位、星曜、亮度和四化数据；分析器负责在不混淆时间层级的前提下，解释十二宫、三方四正、星曜组合和格局。

星曜作用强度、五行交互和量化参数属于独立研究模型。在参数完成标定和验证前，不得将研究草案中的假设数值作为生产分析结论。

分析结果必须满足以下要求：

1. 先陈述事实依据，再给出解释。
2. 本命、大限、流年分别独立成盘、独立分析。
3. 独立分析完成后才允许跨层叠加。
4. 流月、流日、流时按用户需要生成，不默认展开全部内容。
5. 每条四化、格局和结论都必须标明来源盘层。
6. 短期运势只能作为触发信号，不能反过来改写先天结论。
7. 不同流派或存在争议的规则必须标注来源、严格度和规则版本。
8. 宫位负责确定作用对象与领域，星曜负责描述作用机制与表现方式。
9. 宫位和星曜的衍生解释必须能够追溯到原始定义。

### 1.1 宫位与星曜的解释顺序

程序生成解释时必须遵循：

```text
宫位原始定义
→ 当前场景对应的宫位对象
→ 星曜原始定义
→ 星曜在该宫位中的表现方式
→ 亮度、四化、组合与格局修正
```

例如父母宫的原始定义包括“哺育、保护盘主的来源”和“对盘主拥有直接授权、约束或裁决权的上位者”。所以在家庭场景可对应父母或主要照护者，在职场场景可对应直属领导，在教育场景可对应教师或导师，在制度场景可对应证照、文书和审核单位。这些衍生对象都必须引用同一个原始定义，不能作为互不相关的固定断语。

## 2. 核心概念

### 2.1 时间层级

| 层级 | 标识 | 时间范围 | 作用 |
|---|---|---:|---|
| 本命 | `natal` | 一生 | 先天底盘、能力倾向与长期结构 |
| 大限 | `decade` | 十年 | 当前阶段的环境、主线与承载条件 |
| 流年 | `annual` | 一年 | 年度主题与事件级触发 |
| 流月 | `monthly` | 一月 | 月度节奏与阶段推进 |
| 流日 | `daily` | 一日 | 当天触发与短期表现 |
| 流时 | `hourly` | 一时辰 | 短时行动窗口 |

本命、大限、流年属于固定主分析。流月、流日、流时属于按需短期分析。

### 2.2 三方四正

分析任意宫位时，该宫位是当前的焦点宫。它的三方四正包括：

- 本宫；
- 两个三合宫；
- 对宫。

不能只读取本宫星曜，也不能把三方四正中的所有星曜当成同宫星曜。本宫、三合、对宫的关系必须保留在证据中。

### 2.3 星曜组合与格局

星曜组合是局部结构，例如两颗主星同宫。格局是满足特定宫位关系、星曜集合、亮度、四化及吉煞条件后形成的整体结构。

格局判断至少应支持：

- `formed`：必要条件完整，正式成格；
- `strengthened`：获得亮度、禄权科或吉曜增强；
- `weakened`：关键条件偏弱，但未被完全破坏；
- `broken`：核心条件遭遇明确破格因素；
- `tendency`：只满足部分条件，只能称为格局倾向。

不得因为相关星曜“出现过”就直接判定成格。杀破狼等星系结构也不应自动等同于吉格或凶格。

### 2.4 格局归属焦点宫

格局必须归属于本次分析的焦点宫，而不是一律归属于盘主自身。分析器应依次以十二宫为焦点，分别读取该宫的三方四正并判断格局：

```text
命宫三方四正命中格局 → 作用于盘主自身
父母宫三方四正命中格局 → 作用于父母宫所代表的人物与事务
官禄宫三方四正命中格局 → 作用于事业、职位与工作方式
```

例如，同一盘层的禄、权、科会入命宫三方四正，表示盘主自身形成三奇嘉会；会入父母宫三方四正，则表示父母、长辈、文书、教育或制度资源领域呈现三奇嘉会的组合效果。

十二宫的默认归属如下：

| 焦点宫 | 默认作用主体或领域 |
|---|---|
| 命宫 | 盘主自身、人格与总体能力 |
| 兄弟宫 | 兄弟姐妹、同辈与合作关系 |
| 夫妻宫 | 配偶、伴侣与亲密关系 |
| 子女宫 | 子女、创造、作品与传承 |
| 财帛宫 | 财富、收入方式与资源运用 |
| 疾厄宫 | 身体、体质、压力与健康管理 |
| 迁移宫 | 外部环境、出行、异地与社会表现 |
| 奴仆宫 | 朋友、部属、团队与合作网络 |
| 官禄宫 | 事业、职位、职责与工作方式 |
| 田宅宫 | 家庭、居所、不动产与内部环境 |
| 福德宫 | 精神状态、兴趣、享受与内在满足 |
| 父母宫 | 父母、长辈、文书、教育与制度资源 |

归属宫位描述的是“盘主命盘中该宫所代表的对象和领域”，不等同于替该对象另起本命盘。例如“父母宫形成三奇嘉会”可以解释为父母宫主题得到该格局作用，但不能据此断言父亲或母亲自己的独立命盘也一定形成三奇嘉会。

若传统格局本身限定命宫、财帛宫或其他特定宫位，配置必须通过 `applicable_focus_palaces` 保留限制；只有允许作用于任意焦点宫的规则才能设置为 `"*"`。

## 3. 单一盘层的标准分析流程

本命、大限、流年必须复用同一个盘层分析流程：

```text
建立该层十二宫
→ 逐宫读取本宫事实
→ 逐宫读取三方四正
→ 判断同宫、会照、冲照、夹宫和空宫借星
→ 判断星曜组合
→ 判断格局及成破状态
→ 分析该层四化
→ 生成十二宫独立结论
→ 生成该层全盘主轴
```

### 3.1 十二宫逐宫分析顺序

每个宫位必须按以下顺序处理：

1. **宫位事实**：宫名、宫干地支、命身标记、主星、辅星、煞曜、杂曜及亮度。
2. **本宫组合**：同宫双星、吉曜会聚、煞曜同宫、四化落宫和空宫情况。
3. **三方四正**：保留本宫、两个三合宫和对宫各自的星曜及关系。
4. **格局判断**：输出必要条件、增强因素、减弱因素和破格因素。
5. **四化判断**：区分本宫坐四化、三合会四化和对宫冲四化。
6. **吉煞修正**：吉煞用于修正主星结构，不能覆盖主星和格局的主体含义。
7. **先天或阶段结论**：输出优势、倾向、风险、成立条件及证据，不使用绝对化措辞。

空宫应明确标记，并按规则读取对宫主星作为借星依据；借星不等同于主星实际坐入本宫。

### 3.2 单宫分析结果

建议每宫输出如下结构：

```json
{
  "layer": "natal",
  "palace": "官禄宫",
  "four_directions": {
    "self": "官禄宫",
    "triads": ["财帛宫", "命宫"],
    "opposite": "夫妻宫"
  },
  "facts": [],
  "combinations": [],
  "patterns": [],
  "effect_palace": "官禄宫",
  "effect_subject": "事业、职位、职责与工作方式",
  "strengths": [],
  "risks": [],
  "interpretation": "",
  "confidence": 0.0
}
```

`confidence` 表示当前规则证据的完整程度，不表示对现实事件的统计概率。

## 4. 本命盘分析

本命盘只使用本命十二宫、本命星曜、本命亮度和本命四化。

```text
本命十二宫逐宫分析
→ 本命格局分析
→ 命财官迁等主题组合
→ 本命全盘主轴
```

这一层回答个人原有的性质、能力、倾向、优势、限制与人生结构。不得把大限或流年的阶段现象写成本命特质。

## 5. 十年大限分析

以当前大限命宫为新的命宫起点，建立完整的大限十二宫。星曜的实际落宫位置与其在大限盘承担的功能宫位必须同时保留，并叠加大限宫干四化。

先独立完成：

```text
大限十二宫逐宫分析
→ 大限三方四正
→ 大限星曜组合与格局
→ 大限四化
→ 十年主轴
```

再进行本命与大限叠加，结果分为：

- `continued`：大限延续本命结构；
- `activated`：大限激活本命潜在结构；
- `strengthened`：大限增强本命优势或格局；
- `mitigated`：大限缓解本命压力；
- `conflicted`：大限环境与本命倾向产生冲突；
- `broken`：大限对本命格局形成明确破坏。

## 6. 单独流年分析

以流年命宫为起点建立完整流年十二宫，使用流年天干四化。先独立完成流年十二宫、三方四正、组合、格局和年度主轴，再与本命、大限叠加。

```text
流年独立分析
→ 本命 × 流年
→ 大限 × 流年
→ 本命 × 大限 × 流年综合
```

流年格局只代表当年形成或触发的结构，不得提升为终身格局。

## 7. 流月、流日、流时按需分析

短期层级只在用户指定时间或关注主题时生成：

| 请求层级 | 必须叠加的背景 | 默认分析范围 |
|---|---|---|
| 流月 | 本命 + 大限 + 流年 + 流月 | 完整十二宫或重点宫位 |
| 流日 | 本命 + 大限 + 流年 + 流月 + 流日 | 命宫、三方四正和关注宫位 |
| 流时 | 本命 + 大限 + 流年 + 流月 + 流日 + 流时 | 事务相关宫位和明显触发 |

短期层级必须使用符合时间尺度的措辞：

- 流月描述当月节奏和推进情况；
- 流日描述当天触发与表现；
- 流时描述该时段的行动窗口；
- 不得用流日、流时单独推断长期成败。

只有当相同主题在本命、大限、流年和短期层级重复出现时，才可以提高判断强度。

## 8. 跨层数据隔离

所有参与分析的事实必须包含来源：

```json
{
  "star": "廉贞",
  "transformation": "化忌",
  "source_layer": "annual",
  "source_stem": "丙",
  "physical_palace": "亥",
  "functional_palace": "流年官禄宫"
}
```

程序必须避免：

- 把流年化忌写成本命化忌；
- 把大限宫名写成本命宫名；
- 把流年格局写成终身格局；
- 合并四化时丢失天干及盘层来源；
- 将多个层级的固定文案直接拼接成结论。

## 9. 最终报告顺序

```text
一、本命十二宫先天分析
二、本命格局与全盘主轴
三、大限十二宫独立分析
四、大限格局与十年主轴
五、本命与大限叠加
六、流年十二宫独立分析
七、流年格局与年度主轴
八、流年与大限叠加
九、本命、大限、流年三层综合
十、按需流月、流日或流时分析
```

## 10. 静态配置维护要求

象义词典保存在 `config/ziwei/symbolism_dictionary.json`，星曜组合与基础宫位规则保存在 `config/ziwei/analysis_cases.json`，格局规则独立保存在 `config/ziwei/patterns/`。分析器应先读取象义词典建立基础解释，再分别读取组合规则和格局规则进行匹配及强弱修正。

### 10.1 象义词典

维护宫位与星曜解释时必须遵守：

1. 每个条目先维护 `original_definitions`，再维护 `derived_definitions`。
2. 原始定义只描述稳定、可跨场景复用的基础象义，不能直接堆放职业、事件或吉凶断语。
3. 每条衍生定义必须通过 `derived_from` 引用同一条目中的一个或多个原始定义。
4. `scenario` 说明适用环境，`boundary` 说明不适用范围及现实边界。
5. 修改原始定义或改变衍生映射含义时必须递增 `entry_revision`；改变整体结构时递增 `schema_version`。
6. 新增星曜必须先完成基础象义校订，未经校订的资料不得进入结构化推理。
7. 宫位解释只能确定对象或领域，星曜解释只能确定机制或表现；二者必须组合后才能形成具体宫位结论。

### 10.2 星曜组合与基础宫位规则

维护静态案例和规则时必须遵守：

1. `id` 永久稳定，改名不能改变已有含义。
2. 修改规则时递增 `revision`，并记录 `updated_at`。
3. 每条规则标明 `school`、`strictness` 和 `applicable_layers`。
4. 未经校订的规则设置为 `enabled: false`。
5. 条件只描述可由命盘 JSON 验证的事实。
6. 输出必须包含命中的具体宫位、星曜和关系，不只返回格局名称。
7. 宫位规则结果必须输出 `effect_palace` 和 `effect_subject`，归属于触发判断的焦点宫。
8. 文案使用倾向性和条件性表达，避免保证具体事件必然发生。
9. 正式启用前至少增加一个命中样例和一个不命中样例测试。

### 10.3 格局匹配规则

每个格局在 `config/ziwei/patterns/` 下使用一个独立 JSON 文件维护，由 `_manifest.json` 声明规则集版本和文件数量。新增格局时必须遵守：

1. 使用稳定且以 `pattern.` 开头的 `id`，规则内容变化时递增 `revision`。
2. 只使用规则引擎支持的类型化谓词和 `all`、`any`、`not` 逻辑组合，禁止配置任意代码或 `eval` 表达式。
3. 明确 `applicable_layers` 与 `applicable_focus_palaces`；引擎按盘层、焦点宫分别执行，禁止跨层拼接星曜或四化。
4. `required` 是正式成格的必要条件；只有显式配置 `tendency_conditions` 才能返回 `tendency`，不得用匹配百分比推断“接近成格”。
5. `enhancers`、`weakeners`、`breakers` 分别描述增强、减弱和破格条件，状态优先级为破格、减弱、增强、成格。
6. 每次命中必须返回焦点宫对应的 `effect_palace`、`effect_subject`、必要条件轨迹、修正条件轨迹和星曜物理落宫证据。
7. 每个规则至少维护一个正例和一个反例；涉及同层约束、夹宫或特殊归属时必须增加对应边界样例。
8. 新增谓词时同步更新 `pattern.schema.json`、规则引擎校验、单元测试和接口文档，不能只让某一份配置静默可用。
9. 同一格局包含多个严格变体时，可用 `required_variant_policy` 设置命中数量阈值；接口必须同时返回 `matched_variant_count` 和 `matched_variants`，不能让调用方从叶子条件反推变体。
10. 夹宫格的适用宫位必须服从该格局原文和已确认配置，不得一律推广到十二宫。允许逐宫推广的规则仍归属于被夹焦点宫；原文明定只论命宫、身宫的规则，其他宫位只能输出 `pattern_observation` 现象备注，不得计为格局成立。
11. `observations` 只记录已成格结果中的附加结构与煞曜事实，不改变状态；`ordinary_palace_observations` 只记录非适用宫位的相似现象，不进入格局数量。
12. 原文明示破格且要求保留诊断时，基础结构满足后必须保留 `base_status=formed`，最终输出 `status=broken`；`break_check` 同时返回候选破格星、实际命中星曜及物理落宫、扫描范围和规则说明。

`status` 取值：`formed`（成格）、`strengthened`（增强）、`weakened`（减弱）、`broken`（破格）、`tendency`（显式倾向）。旧 C++ `chart.ge_ju` 继续保留以兼容既有接口，但不是结构化分析的权威来源；Python 配置引擎的逐宫匹配结果才可进入分析碎片和后续 AI 输入。

首批谓词目录：

| 谓词 | 用途 |
|---|---|
| `star.contains` / `star.contains_all` | 指定范围包含任一或全部星曜 |
| `star.count` | 按 `equals`、`greater_or_equal`、`less_or_equal` 判断星曜数量 |
| `star.same_palace` | 指定星曜同坐焦点宫 |
| `star.in_triad` / `star.in_opposite` | 指定星曜位于三合宫或对宫 |
| `star.flanks` | 两颗指定星曜分居焦点宫左右相邻宫位 |
| `star.contains_in_scopes` | 指定星曜是否出现在配置的多个范围合集中 |
| `star.one_each_across_branches` | 指定两颗星是否在两个指定地支宫一宫一颗分占；两星同宫或任一宫缺星均不成立 |
| `star.at_physical_branch` | 判断指定星曜是否实际落在指定地支，支持按当前盘层过滤 |
| `palace.is_empty` | 焦点宫是否无主星 |
| `brightness.in` | 指定范围星曜亮度是否命中给定集合 |
| `transformation.contains` / `contains_all` / `not_contains` | 判断指定盘层的四化；可用 `source_layer: "$current_layer"` 限定当前层 |
| `transformation.contains_in_scopes` | 在多个配置范围内按当前盘层判断指定四化是否出现 |
| `annual.lu_kong_dao_ma` | 在流年盘中联合判断禄马位置、沐浴/绝/空亡状态、太岁会照及地劫天空 |
| `transformation.flanks` | 两种指定四化分居焦点宫左右相邻宫位；应以 `source_layer: "$current_layer"` 禁止跨层拼接 |
