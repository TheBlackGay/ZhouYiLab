# 紫微斗数星曜作用模型研究协议 v0.1

> 状态：研究设计草案，尚未进入参数标定  
> 创建日期：2026-08-31  
> 适用项目：ZhouYiLab 紫微斗数结构化分析  
> 配套准则：`docs/ziwei/紫微斗数命盘与运限分析准则.md`

## 1. 研究目的

本研究尝试建立一套配置驱动、可解释、可复核的紫微斗数星曜作用模型。模型从命盘中可验证的宫位、星曜、亮度、四化和空间关系出发，计算星曜在焦点宫中的多维相对作用，再识别传统格局名称并生成可追溯的解释证据。

首阶段研究问题为：

> 能否根据星曜属性、亮度、宫位、三方四正、四化及组合关系，生成稳定、可解释，并能获得研究者或专家一致评价的宫位多维作用结果？

首阶段只验证模型是否忠实表达既定理论及专家判断，不声称模型能够预测现实事件。现实预测效度必须在后续使用独立、匿名且经过合规处理的数据另行验证。

## 2. 研究边界

### 2.1 首阶段纳入范围

1. 只研究本命盘 `natal`。
2. 以本命十二宫中的单个焦点宫作为一次分析单位。
3. 保留本宫、两个三合宫、对宫和左右邻宫的物理关系。
4. 纳入星曜本义、阴阳五行、庙旺利平陷、四化和显式组合规则。
5. 首轮试验仅选择廉贞、七杀及其必要的对照条件。
6. 输出多维作用向量、格局状态和完整计算轨迹。

### 2.2 首阶段排除范围

1. 暂不叠加大限、流年、流月、流日和流时。
2. 暂不把分数解释为现实事件发生概率。
3. 暂不根据个人经历反向修改单个案例的权重。
4. 暂不使用格局名称作为计算输入，避免用结论反推结论。
5. 暂不宣称模型具有统计预测能力、医学诊断能力或确定性人生判断能力。
6. 暂不主张研究具有首创性；相关表述必须经过系统文献检索和现有软件、论文、专利比较。

## 3. 分析单位与归属原则

一次观测记录定义为：

```text
一个命盘
+ 一个盘层
+ 一个焦点宫
+ 一组可验证的星曜与关系事实
→ 一个宫位多维作用结果
```

宫位确定作用对象或领域，星曜确定作用机制。计算结果必须归属于本次分析的焦点宫，并返回 `effect_palace` 与 `effect_subject`。

父母宫出现某种结构，只表示盘主命盘中的父母、长辈、直属权威、教育或文书等父母宫主题受到该结构影响，不等同于替父母另起命盘，也不等同于父母本人的命宫必然形成相同格局。

涉及命主出生时辰、身宫或命主专属条件的规则不得机械转移给其他宫位。此类规则必须明确标记适用宫位和归属边界。

## 4. 核心构念的操作性定义

### 4.1 作用强度

“作用强度”指某项命盘事实在本模型内部对指定分析维度产生的相对增量。它具有以下限制：

- 不是概率；
- 不是吉凶总分；
- 不是现实成就、财富或健康程度的直接测量；
- 只允许在相同模型版本、相同维度和相同计算范围内比较。

首阶段每个维度使用 `[-1.0, 1.0]` 的规范化区间表示方向与相对强弱。该区间只是输出规范；在参数标定完成前，不预设任何星曜的正式数值。

### 4.2 格局

格局是满足特定星曜、宫位、空间关系、亮度、四化或吉煞条件后，对一组稳定交互效果的命名。格局名称是计算结果的标签，不是作用强度的输入变量。

模型必须先完成单星作用和组合交互计算，再判断格局标签。禁止因为已知某组合被称为“富贵格”，就直接提高财富或权力分数。

### 4.3 化学反应

“化学反应”是研究中的工作术语，指两个或多个星曜共同出现时产生、且不能由各单星作用简单相加充分解释的交互增量。

形式化表达为：

```text
组合结果 = 单星贡献之和 + 显式交互增量
```

只有具有来源依据或通过后续标定验证的交互增量才能进入正式模型。

### 4.4 五行关系

五行生、克、泄、耗、比和用于描述星曜之间可能的作用方向，但不能单独决定吉凶。相同的五行关系在不同星曜本义、亮度、宫位和四化条件下可以产生不同结果，因此五行关系只作为交互特征之一。

## 5. 输入变量字典

### 5.1 命盘事实变量

| 变量 | 类型 | 说明 |
|---|---|---|
| `chart_id` | string | 匿名命盘或合成案例标识 |
| `source_layer` | enum | 首阶段固定为 `natal` |
| `focus_palace` | enum | 本次分析的焦点宫 |
| `physical_palace` | enum | 星曜实际落入的宫位 |
| `earthly_branch` | enum | 物理宫位地支 |
| `relation` | enum | `self`、`triad`、`opposite`、`adjacent_left`、`adjacent_right` |
| `star` | string | 星曜稳定名称 |
| `brightness` | enum | 庙、旺、得、利、平、不、陷；缺失必须显式标记 |
| `transformation` | enum/null | 化禄、化权、化科、化忌或空值 |
| `transformation_source` | string/null | 四化天干及盘层来源 |
| `is_body_palace` | boolean | 该物理宫位是否为命主身宫 |

排盘事实只能由排盘模块生成，研究模型不得修改或补造。

### 5.2 星曜固有变量

每颗星曜至少维护：

- 阴阳属性；
- 五行属性及存在争议时的流派版本；
- 可跨宫位复用的原始作用机制；
- 基础维度方向；
- 可参与的交互规则；
- 来源、修订版本和校订状态。

星曜固有变量不得包含“必然从事某职业”“必然发生某事件”等场景断语。

### 5.3 情境修正变量

首阶段需要预留但尚不赋正式权重的修正项：

| 修正项 | 作用 |
|---|---|
| 亮度 | 调整星曜机制能否充分、稳定地表达 |
| 宫位适配 | 调整星曜机制与焦点宫主题的适配程度 |
| 空间关系 | 区分本宫、三合、对宫和夹宫的作用路径 |
| 四化 | 对资源、权力、表达、阻滞等维度施加定向修正 |
| 五行关系 | 描述星曜之间的支持、约束、转化或消耗 |
| 特定组合 | 表示传统理论中不可被简单相加替代的交互增量 |

## 6. 输出维度字典 v0.1

首轮廉贞七杀实验采用十一个研究维度，定义已通过 `ADR-001` 冻结。冻结只约束首轮实验，后续仍可依据预先规定的重新评审条件修订。

| 维度 ID | 中文名 | 操作性定义 |
|---|---|---|
| `resource_mobilization` | 资源获取与调度 | 识别、取得、交换和配置可用资源的倾向 |
| `authority_influence` | 权威与影响 | 获得授权、承担统摄责任、建立秩序并影响他人决策的倾向 |
| `execution_action` | 执行与行动 | 形成决定、投入行动并将计划推进为结果的倾向 |
| `cognition_planning` | 认知与规划 | 吸收信息、辨析关系、形成判断并规划路径的倾向 |
| `communication_expression` | 沟通与表达 | 将思想和信息转化为语言、文字、作品或公共表达的倾向 |
| `stability_accumulation` | 稳定与积累 | 延续、储备、重复建设和形成长期成果的倾向 |
| `change_initiative` | 变化与开创 | 打破既有状态、适应变化并开启新路径的倾向 |
| `relationship_cooperation` | 人际与协作 | 建立关系、协调角色、获得或提供支持的倾向 |
| `emotional_intensity` | 情绪感受强度 | 对内外刺激产生情绪感受、反应和波动的相对强度 |
| `desire_drive` | 欲望与驱动力 | 追求目标、满足需求、获得体验或占有资源的内在驱动力强度 |
| `conflict_risk` | 冲突与风险 | 压力、失衡、对抗、损耗和不确定性暴露程度 |

每个维度的纳入项、排除项和正负方向以 `config/ziwei/research/dimension_dictionary.json` 为准。正值表示该维度定义的方向增强，不统一表示吉；例如情绪感受强度的正值表示反应更强，冲突与风险的正值表示风险暴露增加。禁止把全部维度直接相加生成未经定义的“总吉凶分”。

## 7. 概念计算模型

首阶段只定义计算结构，不确定具体数值：

```text
单星有效贡献
= 星曜基础向量
× 亮度修正
× 宫位适配修正
× 空间关系修正
+ 四化定向修正

组合有效贡献
= 五行关系修正
+ 显式星曜交互增量
+ 格局增强、减弱或破格修正

焦点宫结果
= 所有可追溯贡献按维度聚合
```

实现时每个中间项都必须返回：

- 配置 ID 和版本；
- 输入事实；
- 修正前数值；
- 修正系数或增量；
- 修正后数值；
- 作用维度；
- 来源证据与置信等级。

任何截断、归一化或冲突合并策略都必须显式记录，不能只返回最终分数。

## 8. 证据等级与参数状态

### 8.1 证据等级

| 等级 | 类型 | 说明 |
|---|---|---|
| `E1` | 原始文献 | 可定位版本、篇章和原文的古籍材料 |
| `E2` | 注疏或流派规则 | 可定位作者、流派或正式出版来源的解释 |
| `E3` | 多来源现代解释 | 两个以上可追溯现代来源的相近解释 |
| `E4` | 单一现代解释 | 单一作者、课程、软件说明或用户研究材料 |
| `E5` | 项目假设 | 为形成可检验模型而提出、尚未获得外部支持的解释 |
| `E6` | 经验标定结果 | 由预先规定的数据和方法估计出的参数 |

证据等级表示来源类型，不自动代表真伪或权威高低。互相冲突的来源必须并列保存，不能以更高编号覆盖更低编号。

### 8.2 参数状态

每项权重必须处于以下状态之一：

- `proposed`：待讨论假设；
- `reviewed`：已经过项目内部语义校订；
- `pilot_calibrated`：已通过首轮小样本标定；
- `validated`：已通过预先规定的独立验证；
- `deprecated`：保留历史但不参与新计算。

未经标定的参数不得显示超过其证据支持范围的数值精度。

## 9. 可检验假设

### H1：解释一致性

在隐藏格局名称的情况下，不同研究者或专家对同一组命盘事实给出的维度方向应达到预先规定的一致性标准。

### H2：交互增量必要性

包含显式星曜交互项的模型，对专家综合评分的拟合应优于只将单星作用相加的基线模型。

### H3：情境修正有效性

加入亮度和四化修正后，模型对成对对照案例的排序应比不含这些修正的模型更符合预先记录的专家排序。

### H4：可追溯性

任意最终维度结果都应能完全分解到排盘事实、配置版本和中间修正项；无法追溯的贡献应为零。

具体一致性指标、阈值、样本量和统计方法必须在采集评分前预先登记，不能观察结果后再选择有利指标。

## 10. 首轮廉贞七杀试验

### 10.1 目的

验证模型能否区分单星相加、五行约束、亮度变化、禄权支持和化忌风险，而不是验证“雄宿乾元格必然富贵”。

### 10.2 合成对照组

除表中变量外，其余条件保持一致：

| 组别 | 条件 | 主要比较目的 |
|---|---|---|
| `LQ-A` | 廉贞、七杀在未宫同宫，采用亮度表中的廉贞利、七杀庙，不附加四化 | 建立可达的双星基础组合 |
| `LQ-B` | `LQ-A` + 三方四正见同层化禄 | 单独检验化禄支持信号 |
| `LQ-C` | `LQ-A` + 三方四正见同层化权 | 单独检验化权支持信号 |
| `LQ-D` | `LQ-A` + 三方四正同时见同层化禄、化权 | 检验禄权信号并存 |
| `LQ-E` | `LQ-A` + 廉贞化忌 | 检验化忌与风险变化 |
| `LQ-F` | 廉贞、七杀不同宫，改为三合或对宫关系 | 检验同宫交互是否不可替代 |
| `LQ-G` | 仅廉贞 | 单星基线 |
| `LQ-H` | 仅七杀 | 单星基线 |

地支位置、具体亮度状态和四化来源必须在案例配置中明确，不允许使用“条件较好”“禄权足够”等不可计算描述。

`LQ-A` 至 `LQ-H` 是用于隔离局部机制的最小事实夹具，不代表完整命盘。夹具必须明确声明其完整性边界；星曜地支与亮度必须符合现有亮度表。由于廉贞七杀同宫只在丑、未出现，且当前亮度表两处均为廉贞利、七杀庙，首轮不构造不存在的“同宫落陷”案例。亮度效应应在后续单星位置实验中独立研究。

### 10.3 盲评要求

1. 评分材料只展示命盘事实，不展示“雄宿乾元格”等格局名称。
2. 评分者按十一个维度分别给出方向、相对强弱和简短依据。
3. 收集评分前冻结案例和评分说明。
4. 先比较评分者之间的一致性，再讨论模型参数。
5. 若专家无法对某维度形成稳定判断，应删除、合并或重新定义该维度，不得强行拟合。

## 11. 验证阶段

### 阶段 A：语义与构念验证

确认变量定义、星曜本义、作用方向和证据引用准确。此阶段不使用现实人生结果。

### 阶段 B：专家一致性与模型比较

使用冻结的合成案例进行盲评，比较：

- 单星相加基线；
- 加入亮度和空间关系的模型；
- 加入四化的模型；
- 加入显式交互项的完整模型。

### 阶段 C：外部效度验证

只有前两阶段通过后，才设计匿名真实样本研究。现实指标必须预先定义为可观察变量，不能使用“人生很好”“比较富贵”等模糊标签。

训练、调参与最终验证数据必须隔离。不得使用同一批案例既发现规则又证明规则。

## 12. 数据、伦理与复现要求

1. 真实出生信息和人生经历属于敏感个人数据，采集前必须取得明确授权并最小化保存。
2. 研究数据使用匿名 ID，不在公开仓库提交姓名、精确出生资料或可识别经历。
3. 涉及健康、司法、财富等结论时只能研究可观察变量，不得输出诊断或确定性判断。
4. 每次实验记录代码提交、配置版本、数据版本、随机种子和运行环境。
5. 原始评分记录只追加，不覆盖；排除样本必须记录预先规定的理由。
6. 正向、负向和不显著结果均应保留，避免只报告支持传统结论的案例。

## 13. 配置与实现路线

研究协议通过评审后，依次建立：

1. `config/ziwei/research/dimension_dictionary.json`：冻结的输出维度、方向和边界。
2. `config/ziwei/research/star_energy_profiles.json`：星曜属性、基础向量、来源与参数状态。
3. `config/ziwei/research/influence_coefficients.json`：亮度、宫位、关系、四化和盘层修正。
4. `config/ziwei/research/star_interactions.json`：五行关系和特定星曜交互增量。
5. `config/ziwei/research/experiments/lianzhen_qisha_v0.1.json`：首轮合成对照案例。
6. 独立的实验运行器：读取冻结配置，输出逐项计算轨迹和可比较结果。

现有 `config/ziwei/patterns/` 继续负责传统格局结构识别，但不得直接充当作用分数来源。格局规则和能量模型通过稳定 ID 建立引用关系。

### 13.1 首轮实验运行器

离线运行全部冻结案例：

```bash
python3 web/ziwei_research_engine.py --pretty
```

只运行一个案例：

```bash
python3 web/ziwei_research_engine.py --case LQ-D --pretty
```

运行器负责：

1. 校验维度词典、星曜档案、交互规则、实验案例及亮度表的版本一致性。
2. 校验案例中星曜地支与亮度表一致。
3. 分别输出单星机制、基础交互、修正项命中轨迹和事实证据。
4. 按维度建立信号索引，但不聚合、不评分、不生成格局名称。
5. 验证 `LQ-A` 至 `LQ-H` 的实际触发项与冻结预期一致。

实验运行器是研究工具，不接入面向 App 用户的生产命盘解读 API。本地 HTTP 服务只暴露不含答案映射的盲评包，用于评分页面。受控四化刺激必须在输出证据中保留 `fact_status: "controlled_stimulus"`，调用方不得将其误认为完整命盘事实。

## 14. 首阶段完成标准

同时满足以下条件才进入正式参数开发：

1. 十一个输出维度均有无歧义的操作性定义，并通过版本化决策记录冻结。
2. 廉贞、七杀的原始机制和五行属性均有可定位来源。
3. 廉贞七杀对照组的所有输入变量可以由程序直接验证。
4. 评分说明和盲评表在收集数据前冻结。
5. 明确一致性指标、通过阈值和最低评分者数量。
6. 明确哪些参数来自文献，哪些来自项目假设，哪些允许由数据标定。
7. 可从最终输出完整回溯到每个输入事实和配置版本。

## 15. 当前未决问题

1. 亮度等级应使用连续系数还是分段增量。
2. 三合、对宫、夹宫的作用是否适合使用固定衰减系数。
3. 四化应作为乘数、增量，还是改变星曜作用机制的条件开关。
4. 五行关系能否跨星曜使用通用参数，还是必须按具体星对分别配置。
5. “禄权足够”等传统语言如何转换为明确且可复核的条件。
6. 专家一致性不足时，应优先修订构念、评分说明还是流派分组。

所有未决问题均应通过版本化决策记录解决，不在代码中隐式决定。
